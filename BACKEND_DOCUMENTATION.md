## 2. PROJECT OVERVIEW

### Core Purpose
The `job-posting` backend (internally referred to as `BusinessClinic API`) is a multi-tenant recruitment and verification platform designed to connect **Students**, **Companies**, and **System Administrators**. It provides capabilities for user registration, multi-role authentication, student profile verification, company registration and founder management, job posting lifecycle management, student job applications with resume uploads, and administrative moderation.

## 7. DETAILED ENDPOINT DOCUMENTATION

Below is a detailed breakdown of core operational endpoints across all business modules.

### `POST /api/v1/users/register`
- **Purpose**: Registers a new user (`STUDENT`, `COMPANY`, or `ADMIN`) in the system with optional profile picture upload.
- **Authentication**: None (Public).
- **Authorization**: Public.
- **Request Headers**: `Content-Type: multipart/form-data` or `application/json`.
- **Request Body**:
  ```json
  {
    "name": "john doe",
    "email": "john@example.com",
    "username": "johndoe",
    "password": "SecretPassword123",
    "role": "STUDENT",
    "companyId": "optional_company_id"
  }
  ```
- **Files**: `profileImage` (optional file field handled by Multer).
- **Execution Flow**:
  1. Validates required body fields (`name`, `email`, `username`, `password`).
  2. Queries `User` model for existing user with `$or: [{email}, {username}]`. If found, throws `ApiError(400)`.
  3. Handles `req.file?.path`: if present, calls `uploadOnCloudinary()`. If missing, assigns hardcoded default fallback Cloudinary image URL (`https://res.cloudinary.com/...`).
  4. Calls `User.create()` setting `status: "PENDING"`. Pre-save hook hashes password with `bcrypt.hash(..., 10)`.
  5. Queries created user minus `password` and `refreshToken`.
  6. Returns HTTP 201 with `ApiResponse(201, { user, companyId }, "User registered successfully")`.
- **Error Cases**:
  - `400`: Missing required fields or duplicate email/username.
  - `500`: Cloudinary upload failure or database creation failure.

### `POST /api/v1/users/login`
- **Purpose**: Authenticates a user with email and password, issuing access and refresh JWTs as HTTP-Only cookies and response JSON.
- **Authentication**: None (Public).
- **Request Body**:
  ```json
  {
    "email": "john@example.com",
    "password": "SecretPassword123"
  }
  ```
- **Execution Flow**:
  1. Validates `email` and `password`.
  2. Finds user by `email`. Throws `ApiError(400)` if not found.
  3. Executes `user.isPasswordCorrect(password)` via `bcrypt.compare`. Throws `ApiError(400)` if incorrect.
  4. Generates Access Token (`ACCESS_TOKEN_SECRET`, `ACCESS_TOKEN_EXPIRY`) and Refresh Token (`REFRESH_TOKEN_SECRET`, `REFRESH_TOKEN_EXPIRY`).
  5. Saves `refreshToken` to user document in MongoDB using `{ validateBeforeSave: false }`.
  6. Sets `accessToken` and `refreshToken` cookies (`httpOnly: true`, `secure/sameSite` dynamic based on `NODE_ENV`).
  7. Returns HTTP 200 with user data (excluding password/refreshToken) and tokens.

### `POST /api/v1/jobs/create`
- **Purpose**: Creates a new job posting attached to a company.
- **Authentication**: Required (`verifyJWT`).
- **Authorization**: Required (`checkNotBlocked`, `verifyRole("COMPANY")`).
- **Request Body**:
  ```json
  {
    "title": "Software Engineer",
    "company": "65ab1234c567890123456789",
    "description": "Full-stack developer role",
    "requirements": ["React", "Node.js", "MongoDB"],
    "location": "Remote",
    "salary": "$100,000",
    "jobType": "FULLTIME",
    "applicationDeadline": "2026-12-31T23:59:59.000Z"
  }
  ```
- **Execution Flow**:
  1. Validates required fields (`title`, `company`, `description`, `requirements`, `location`, `salary`, `jobType`).
  2. Validates `jobType` enum (`FULLTIME` or `INTERNSHIP`).
  3. Parses comma-separated string requirements into array if string is supplied.
  4. Creates `Job` document with `status: "ACTIVE"` and `createdBy: req.user._id`.
  5. Populates `company` and `createdBy` fields and returns HTTP 201 (`ApiResponse(200, createdJob)` - Note: HTTP status 201, `ApiResponse` code 200).

---

### `POST /api/v1/applications/submit`
- **Purpose**: Submits a student's application for an active job with resume document upload.
- **Authentication**: Required (`verifyJWT`).
- **Authorization**: Required (`checkNotBlocked`).
- **Files**: `resume` (optional/required multipart file field).
- **Execution Flow**:
  1. Validates `jobId` and checks if job exists.
  2. Validates company status (throws 400 if company `status === "BLOCKED"`).
  3. Validates job status (throws 400 if job `status !== "ACTIVE"`).
  4. Checks `applicationDeadline`; throws 400 if passed.
  5. Queries `Application` collection for existing `({ job: jobId, student: req.user._id })`. Throws 400 if already applied.
  6. If file is present, calls `uploadDocumentOnCloudinary(req.file.path)` (uploaded to `resumes` folder as `resource_type: "raw"`).
  7. Creates `Application` document with `status: "APPLIED"`.
  8. Populates job, company, student and returns HTTP 201.

---

### `POST /api/v1/invites/send`
- **Purpose**: Allows a company founder to invite another existing user to join as a co-founder.
- **Authentication**: Required (`verifyJWT`).
- **Authorization**: Required (`checkNotBlocked`, `verifyRole("COMPANY")`, caller must be a founder in `company.founders`).
- **Request Body**: `{"companyId": "...", "email": "cofounder@example.com"}`
- **Execution Flow**:
  1. Finds company and verifies caller is present in `company.founders`.
  2. Verifies invited email belongs to an active, non-blocked `User`.
  3. Verifies user is not already a founder and has no `PENDING` invite.
  4. Creates `CompanyInvite` document setting `expiredAt` to 7 days from creation. Returns HTTP 201.

---

### `POST /api/v1/verifications/`
- **Purpose**: Submits a verification application for a Student or Company profile after onboarding.
- **Authentication**: Required (`verifyJWT`).
- **Request Body**:
  ```json
  {
    "applicantType": "STUDENT",
    "studentProfileId": "65ab1234c567890123456789",
    "companyId": null
  }
  ```
- **Execution Flow**:
  1. Validates `applicantType` (`STUDENT` or `COMPANY`).
  2. Checks for existing `PENDING` request for `userId`. Throws 400 if duplicate.
  3. Validates referenced ID based on type.
  4. Creates `VerificationApplication` with `status: "PENDING"`. Returns HTTP 201.

## 8. AUTHENTICATION SYSTEM

### Mechanisms
- **JWT Standard**: Dual-token architecture using JSON Web Tokens.
  - **Access Token**: Short-lived, stored in HTTP cookie `accessToken` or passed in `Authorization: Bearer <token>` header. Contains `_id` and `role`. Signed with `process.env.ACCESS_TOKEN_SECRET`.
  - **Refresh Token**: Long-lived, stored in HTTP cookie `refreshToken` or request body, and persisted in `User.refreshToken` database field. Signed with `process.env.REFRESH_TOKEN_SECRET`.
- **Password Hashing**: `userSchema.pre("save")` automatically hashes modified passwords with `bcrypt` (salt rounds: 10).
- **Password Verification**: Instance method `userSchema.methods.isPasswordCorrect(password)` calls `bcrypt.compare`.

### Authentication Execution Diagram

```text
Client Request
  ↓
Extract Token: req.cookies?.accessToken || req.header("Authorization")?.replace("Bearer ", "")
  ↓
jwt.verify(token, process.env.ACCESS_TOKEN_SECRET)
  ↓
User.findById(decodedToken._id).select("-password -refreshToken")
  ↓
Attach req.user = user and req.role = user.role
  ↓
next()
```

## 12. BUSINESS LOGIC BY DOMAIN

### User & Authentication Domain
- Password modification automatically triggers bcrypt re-hashing in Mongoose pre-save hook.
- Refresh tokens are verified against DB-stored `user.refreshToken` to prevent replay attacks.
- Profile photos update triggers deletion of old custom photos from Cloudinary while preserving the default avatar.

### Student Management Domain
- Students must submit profile data (branch, college, year) and upload a verification document.
- Updating a verification document automatically resets profile status to `"PENDING"` for re-approval.

### Company & Founder Domain
- Any user with role `"COMPANY"` can register a company, automatically becoming its initial founder.
- Founders can send invitations via email to existing users to become co-founders. Accepting an invite adds the user to `company.founders` and elevates their role to `"COMPANY"`.

### Job & Application Lifecycle
- Only company founders and admins can post jobs.
- Job search excludes expired deadlines for `STUDENT` users.
- Students can apply with a resume, but cannot apply twice to the same job.
- Students can only withdraw/delete applications within **24 hours** of submission.
- Reviewing an application with status `"OFFER"` strictly requires an `offerLetterUrl`.
